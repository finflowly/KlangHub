# KlangHub 0.0.1

**One music. Every room.**

The first public cut of a native Windows multiroom audio hub. It casts the sound of your desktop to
Chromecast and Google Cast devices and groups, keeps the metadata and the quality on the way, and is
built so that a second protocol arrives as a provider rather than as a rewrite.

This is a foundation release. The version number is honest.

## What this cut contains

**Sound**
- Captures desktop output or a microphone / line-in input (WASAPI loopback), capped at 48 kHz
  because Cast receivers mix there anyway.
- Streams WAV 16/24/32-bit, FLAC (lossless) or MP3 128/320. A fresh installation streams **FLAC with
  a ten-second buffer** — lossless and compressed, which is what survives a wireless link that
  uncompressed 24-bit can overrun.

**Rooms**
- Finds Chromecast and Google Cast devices and groups over mDNS, and recovers a device that
  announces itself over IPv6 only.
- Plays to several rooms at once. Play, pause, stop, volume and mute per room, with a per-room volume
  ceiling and a room fader that keeps the balance between the speakers behind it.
- Rooms can be named, the cards grouped by room, and room presets stored.

**What is playing**
- Five metadata sources — the Windows now-playing session, Clementine's network remote, file tags,
  the player's window title, the file name — merged into one answer and sent with the stream.
- Branded now-playing artwork, served from the local HTTP server and reachable only with the run's
  session secret.

**The application**
- Runs from the notification area, starts with Windows, optional keyboard shortcuts.
- **24 languages**: every official EU language, fully translated, listed under its own name.
- A per-user installer that needs no administrator rights, and 734 tests behind the build.

## What is deliberately not in it

Named here so nobody has to find out by being disappointed.

- **AirPlay and Snapcast do not play.** Both are discovered and classified, and both refuse to open a
  session. AirPlay needs HomeKit pairing and an ALAC/RTP sender; Snapcast needs a snapserver feed and
  JSON-RPC control. Neither is faked.
- **The TV receiver has never run on a television.** The custom CAF v3 receiver is complete in the
  repository and needs a hosted URL and a registered Cast application id. Its one known unfixed
  weakness is written down in `receiver/README.md`, together with why the fix waits for that first
  run instead of shipping untested.
- **Rooms are not synchronised** in the sense a multiroom product means. Several receivers buffer
  independently and drift. Real synchronisation needs a receiver we control and a per-device latency
  offset.
- **No lip-sync.** The buffer that keeps music playing makes video impossible. This is a music hub.
- **Spotify Connect and Tidal Connect are not planned.**

## Requirements

Windows 10 or 11, 64-bit, and a Cast device on the same network. Windows Firewall has to let KlangHub
accept incoming connections on your private network — the speaker *fetches* the stream from your PC,
so it has to be able to reach it.

## Install

`KlangHub-0.0.1-Setup.exe` installs per user and needs no administrator rights.

**Windows will warn, and that is expected.** The setup is not code-signed; a certificate costs money
this project does not spend. SmartScreen shows *"Windows protected your PC"* — the way through is
**More info → Run anyway**. Anyone who would rather not do that can build from source:

```
dotnet build Source/KlangHub.sln -c Release
```

.NET 10 SDK required. The shipped build is self-contained and needs no runtime installed.

## Known issues

- A small speaker fed uncompressed high-resolution audio can play for about a minute and then return
  `detailedErrorCode: 102`. That is the receiver's buffer, not the network — use FLAC, which is the
  default.
- A device that changes its DHCP address can briefly appear twice. It heals on the next
  announcement, or immediately with *Find rooms again*.
